## 1. 定位与场景（规格书 §2.1）

仪器/设备每天产生大量日志（时间戳 / 通道 / 状态码 / 数值）。现场排障时要在几秒内回答：哪个通道异常最多？状态码分布如何？数值范围多少？——用命令行工具一键统计，而不是把日志拖进 Excel。

这就是「Linux 应用开发」最日常的一类活：**读文件 → 解析 → 统计 → 输出**。P1 把它做小、做透，P2/P3/P4 再往上叠线程、网络、串口。

## 2. 数据格式（规格书附录 A.1）

每行一条记录，空格分隔 4 个字段：

```text
2026-11-05T10:00:00.123 CH1 OK 25.3
2026-11-05T10:00:00.223 CH2 WARN 60.1
2026-11-05T10:00:00.323 CH1 ERR 99.9
```

| 字段 | 取值 | MVP 处理方式 |
|---|---|---|
| 时间戳 | `YYYY-MM-DDTHH:MM:SS.mmm`（本地时区） | **只做字符串切分，不转时间**（别过早引时间库） |
| 通道 | `CH1`–`CH8` | 字符串比较 |
| 状态 | `OK` / `WARN` / `ERR` | 字符串比较；其它值 = 未知状态 = 坏行 |
| 数值 | float（A.1 只规定 float，本样本统一 1 位小数） | `strtod`/`sscanf`，**必须检查返回值** |

坏行（约 2%，三类轮换）→ **计入 `bad_lines` 并跳过，不崩溃**：

| 类型 | 长什么样 | 解析器应在哪一步拒绝 |
|---|---|---|
| 字段数不对 | `2026-11-05T10:00:05.000 CH1 OK` | 切分后字段数 ≠ 4 |
| 状态未知 | `2026-11-05T10:00:10.000 CH3 FATAL 54.4` | 状态不在白名单 |
| 数值非法 | `2026-11-05T10:00:15.000 CH2 OK abc` | `strtod` 失败 / 尾部有残留 |

## 6. 常见坑（规格书 §2.5 + 本工作区实测）

1. **`sscanf` 不检查返回值** → 坏行被当正常行，统计悄悄错。
2. **时区/毫秒**：MVP 只做字符串切分，不要过早引入时间库。
3. **行太长超过缓冲** → 截断后字段全错；要限制行长或动态扩展（`getline`）。
4. **空文件 / 全坏行** → 统计结果除零（avg）；要先判有效行数。
5. **编码**：样本按 ASCII，中文注释才 UTF-8。
6. **`.gitignore` 的 `*.log` 会吞掉样本**（本工作区实测）：默认所有 `*.log` 都被忽略；已对样本目录加例外，只放行 `devlog_1000.log`（另有 `!docs/**/*.log` 是历史规则），10 万行样本现场生成不入库。
7. **换行符**：Windows 侧写出的 CRLF 会让行尾 `\r` 留在最后一个字段——按空格 `strtok`/手工切分时 `strtod` 尾部检查失败（实测 1000 行全判坏），换成 `sscanf("%s")` 又可能因 `\r` 被当空白而侥幸不坏（取决于切分写法，别赌）。→ 样本生成器强制 LF；本仓库 Windows 侧 `core.autocrlf=true`，checkout 时还会再转一次 → 仓库根 `.gitattributes` 已设 `* text=auto eol=lf` + `*.log -text`（样本禁止任何转换）；解析时也顺手去掉行尾 `\r`/`\n`。
8. **对照统计的舍入**：`value_avg` 是 2 位小数；C 侧用 `double` 累加，允许最后一位 ±0.01 的舍入差。

**样本实测数字**（1000 行）：有效 980 / 坏行 20（缺字段 7、未知状态 7、非法数值 6）；状态 OK 691 / WARN 199 / ERR 90；数值 min 20.1、max 100.0、avg 61.36。`stats.txt` 还含 `status_<S>_channel_<CH>` 与 `status_<S>_value_min/max/avg`，供 `--status` 过滤结果对照。

**为什么固定种子、坏行固定成 2%**：① 同参数重生成逐字节一致 → 单测/对照答案稳定；② 坏行按类型轮换 → 三类拒绝路径都能被测到；③ 坏行位置固定（第 50、100、150… 行）→ 方便 `sed -n '50p'` 直接看。
