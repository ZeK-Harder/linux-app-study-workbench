# 理解清单 · P0 hello-linux（示例，照着填自己的）

> 这是填好的示例，用来学“理解清单怎么填”。P1 起自己写。

## 一、数据流图

`main(argc, argv)` → `printf("Hello...")` → libc 缓冲 → `write(1, buf, n)` 系统调用 → 内核 → 终端
→ `sum_to(n)` 循环累加 → `printf("sum...")` → 同样走 write → `return 0` → libc 退出 → `exit_group` 系统调用

能画：程序入口不是 main，是 `_start`（libc 启动代码）→ 准备 argc/argv → 调 main → main 返回 → exit。

## 二、关键机制（3 条）

1. **编译四阶段**
   - 为什么：把“人读的 C”变成“机器能加载的 ELF”，每个阶段职责单一，便于查错。
   - 删了会怎样：没有链接，`printf` 找不到实现；没有预处理，`#include` 不展开。
   - 换个做法：`gcc -E`（预处理）、`-S`（汇编）、`-c`（目标文件）、直接链接，能分开看每一步。
2. **`-g` 与调试信息**
   - 为什么：gdb 靠 DWARF 调试信息把机器码映射回源码行号/变量名。
   - 删了会怎样：gdb 只能看寄存器/汇编，看不到变量和源码行。
   - 换个做法：`-g -O0` 调试版、`-O2` 发布版分开编。
3. **Makefile 的依赖**
   - 为什么：只重编“变了的文件”，大项目才快；`.PHONY` 防止和同名文件冲突。
   - 删了会怎样：每次全量编译；`clean` 可能被同名文件“吞掉”。
   - 换个做法：CMake 生成 Makefile（P2 再学）。

## 三、追问清单（10 题）

1. 从 `.c` 到可执行文件，四步分别做什么？→ 预处理/编译/汇编/链接
2. `-Wall -Wextra` 开了什么？→ 常见警告集合；零警告是习惯
3. 为什么 `-g` 和 `-O2` 一般不同时用？→ 优化会重排/内联，调试信息与源码对不上
4. `printf` 最终走到哪？→ libc 缓冲 → `write(2)` 系统调用
5. `main` 之前谁在跑？→ libc 的 `_start`
6. `argc/argv` 从哪来？→ 内核 execve 传参 → 栈上布局
7. Makefile 里 `$@` `$<` 是什么？→ 目标/第一个依赖
8. `.PHONY` 解决什么问题？→ 目标名与文件名冲突
9. `atoi("abc")` 返回什么？→ 0（无错误区分，真实项目用 `strtol`）
10. `make clean` 删了什么？→ 只需删构建产物，不删源码

## 四、踩坑记录（3 条）

| 现象 | 定位 | 根因 | 修复 |
|---|---|---|---|
| Makefile 报 `missing separator` | 报错行 | 用了空格不是 Tab | 缩进改成 Tab |
| gdb 里看不到变量 | `info locals` | 编译没带 `-g` | CFLAGS 加 `-g` |
| 程序输出没立刻显示 | 重定向到文件时 | stdout 全缓冲 | 换行/fflush 或接受缓冲 |
